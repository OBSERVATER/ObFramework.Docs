# Unity bootstrap and lifetime

Attach the `GameLauncher` generated by `ob init --engine unity` to an active GameObject in your startup scene. The launcher starts one `GameApplication`, `UnityRuntimeHost` owns the persistent Unity objects, and `UnityFrameLoopBridge` connects the framework clock to Unity's PlayerLoop.

## Generated launcher

`GameLauncher.cs` is generated under `Assets/Scripts/Unity/` and creates the same `GameApplication` type that the engine-independent .NET scaffold uses. During `Awake`, the launcher prepares `GameManager` and instantiates `ObFramework/UIRoot` from `Resources`. The supplied prefab uses Unity UI (uGUI). The root provides `Scene`, `Common`, and `Popup` layers. The project supplies its EventSystem and input module.

The generated `GameLauncher.CreateApplication()` passes `ConfigurePlugins()` directly to the business `GameApplication` constructor. Edit `ConfigurePlugins()` to set the clock interval and create the rest of the application's plugins. It supplies a `ClockPlugin` at 30 ticks per second by default. `RuntimeUIRoot` is available for constructing the UI adapter. The framework starts the complete list returned by `GameApplication.CreatePlugins()`.

The application initializes its Architecture, prepares Unity view bindings, and runs `EnterGameAsync`. The launcher's `StartGameAsync()` then runs Unity entry work such as opening a registered window or loading a gameplay scene. The protected overload accepts the application startup cancellation token.

## Minimal launcher

This complete launcher/application declaration starts an application with a clock and an empty Architecture. It intentionally creates no gameplay scene or UI:

```csharp
using System.Threading;
using System.Threading.Tasks;
using ObFramework.Adapter.Unity.Core;
using ObFramework.Core;
using ObFramework.Integrated.Clock;

public sealed class BootstrapLauncher : AGameLauncher
{
    protected override PluginApplication CreateApplication() => new GameApplication();
    public override Task StartGameAsync() => Task.CompletedTask;
}

public sealed class GameApplication : PluginApplication
{
    protected override IPlugin[] CreatePlugins() => new IPlugin[] { new ClockPlugin(1f / 30f) };

    protected override IArchitecture CreateArchitecture(IPluginContext plugins)
    {
        GameArchitecture.InitInterface(plugins);
        return GameArchitecture.Interface;
    }

    protected override Task EnterGameAsync(CancellationToken ct)
    {
        ct.ThrowIfCancellationRequested();
        return Task.CompletedTask;
    }
}

public sealed class GameArchitecture : AArchitecture<GameArchitecture>
{
    protected override void Init() { }
}
```

Use this declaration in a Unity project where the runtime and adapter packages are installed. `ClockPlugin` is needed because application startup binds the supplied frame driver to that plugin. Each `PluginApplication` starts once; create a new instance for a new application lifetime.

## Persistent roots

The generated launcher creates a `GameManager` root. The host owns both the manager and the separately rooted `UIRoot` in `DontDestroyOnLoad`. The top-level UI root preserves the Canvas's Screen Space - Overlay rendering. The launcher follows the startup scene's lifetime.

For a hand-authored launcher, override `UIRootResourceKey` to load a prefab during startup. A launcher using scene-authored UI gets an `OBF Runtime` root and collects the startup scene's `UIRoot` objects. Host shutdown destroys the roots it owns.

## Frame dispatch

`UnityFrameLoopBridge` inserts its own callbacks immediately before Unity's script Update, FixedUpdate and LateUpdate callbacks. It removes only callbacks owned by that bridge on unbind. A duplicate installed OBF bridge is rejected.

View binding preparation runs after Architecture creation and before game entry. Enabled bound Views that implement framework tick interfaces register with the clock; disabling or releasing their controller removes those registrations. Views implementing the enabled lifecycle can defer their first tick until the following frame, preventing a deferred native destruction from receiving a tick in the activation frame.

## Stop and quit

Call `RequestExit()` on the running `GameApplication` to request Player exit. The call returns promptly, so startup callbacks and application tasks can request exit and finish their own work. `StopGameAsync()` is the business shutdown hook. It runs with the Architecture and plugins still available.

```csharp
using ObFramework.Adapter.Unity.Core;

UnityRuntimeHost.Current?.Application?.RequestExit();
```

The Unity host routes `Application.wantsToQuit` through the same exit flow. It awaits application shutdown, releases the persistent roots, and asks the Player to quit. The application's shared stop task handles repeated stop requests. `UnityRuntimeHost.ShutdownAsync()` awaits runtime shutdown and is suitable for replacing the runtime. `OnDestroy` starts cleanup when Unity destroys the host externally.

For a component-owned subscription, `DisposeWhenDestroyed(owner)` registers disposal against `destroyCancellationToken`. `ObExecutionScope.StopWhenDestroyed(owner)` requests scope shutdown and logs failures. Destruction callbacks start asynchronous scope draining; they do not make Unity await its completion. Use the application's awaited shutdown path for work that must finish before dependencies disappear.
